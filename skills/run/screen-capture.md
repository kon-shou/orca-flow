# 画面の記録（run が読む）

設計書に「画面の記録」の節があり、中身が「録らない」でないときに、タスク長が行う。レビューの直しが済んだあと、報告を書く前に録る。報告を書いたあとにコードを直したら、録り直す。

## 古い GIF を消す（最初に行う）

- `git rev-parse --path-format=absolute --git-common-dir` の下の `orca-flow/captures/〈ID〉/` に GIF が残っていれば、道具を探すより前に消す。報告を書いたあとの録り直しのときも同じ。道具がなくても、拡張がつながらなくても消える。

## 道具

- ToolSearch で、ブラウザの拡張（Claude in Chrome など）の道具を探す。GIF を作る道具（`gif_creator` など）とタブを操作する道具を使う。サーバー名の頭を決め打ちしない。
- 道具が見つからなければ、録らない。止めずに、報告の「画面の記録」の節に「録れなかった：道具がない」と書いて進む。

## 録り方

1. アプリを動かす前に、設計書の開く URL へ `curl -q -g -sS --max-time 5 -o /dev/null` でつなぎ（時間の上限は5秒）、終了コード7のときだけ進む（つながらないということ）。答えがあれば録らず（終了コード0。4xx・5xx・時間切れも録らない。4xx・5xx も答えで、ほかのアプリがそのポートを使っている）、28（時間切れ）・52・56・35・60 など、何かが待ち受けていると分かる終了コードも録らず、どれも報告の「画面の記録」の節に「録れなかった：ポートがほかに使われている」と書く。そのほかの終了コード（URL の誤りや道具の失敗など）も録らず、「録れなかった：ポートの確かめが失敗した（終了コード〇）」と書く。このとき自分は何も動かしていないので、何も止めず、片づけもしないで終わる。
2. アプリを動かす前に、`git -c core.quotePath=false status --porcelain --untracked-files=all` の出力を会話に残す（`--ignored` はつけない。worktree の中にファイルを作らない）。そのあと、設計書の起動のしかたで、アプリを背景で動かす。起動の待ちは数分（5分まで）にする。超えたら録らず、報告の「画面の記録」の節に「録れなかった：アプリが起動しない」と書く。
   - 起動のあと、そのポートで答えるまで待つ。答えたら、録る前に、自分が動かしたプロセスが生きていて、そのポートで待ち受けているのが自分のアプリだと確かめる。生きているだけでは足りない（ポートがふさがると別のポートへ移って生き続けるサーバーがあり、答えたのはほかのタスクのアプリかもしれない）。そのポートで待ち受けているプロセスの PID を調べ（Linux は `ss -ltnp`、Mac は `lsof -nP -iTCP:〈ポート〉 -sTCP:LISTEN -t`）、自分が動かしたプロセスかその子孫であることを確かめる。プロセスが死んでいれば録らず、「録れなかった：アプリが起動しない」と書く。待ち受けているのが自分の子孫でなければ録らず、「録れなかった：ポートがほかに使われている」と書く。調べる道具がない・PID が分からないなど確かめられないときも録らず、「録れなかった：自分のアプリか確かめられない」と書く。2つのタスクが同時に確かめを通っても、相手のアプリを録らないための確かめ。
3. 録り始めの前に、時刻の印（`date +%s` の出力）を会話に残す。新しいタブを開き、設計書の流れ（1〜3本）を1本ずつ、操作しながら録る。書き出す GIF の名前は、録るときに `〈ID〉-〈流れの名前〉.gif` と道具に渡して決める。ふだんのプロファイルで、本物のサインインが写るタブを開かない。録る間は `orca-flow status working --note "画面を録っている"` で一言を出す。
4. 手順2でアプリを動かしたあとは、録れたかどうかに関係なく（起動しない・拡張がつながらない・途中で落ちた・録らないと決めた場合を含む）、最後に必ず、手順2で自分が動かしたアプリを止め（止めるのは自分が動かしたものとその子プロセスだけ。ほかのプロセスは止めない）、開いたタブを閉じる。止めたあと、アプリが worktree に残したファイルを、次の決まりだけで片づける。
   - 片づけの `rm -- ` は、`git rev-parse --show-toplevel` の場所、つまり worktree の一番上で流す。`git status` が出すパスは一番上からの形なので、下のフォルダで流すとずれる。
   - 止めたあと同じ `git -c core.quotePath=false status --porcelain --untracked-files=all` を流し、手順2の前の出力になくて新しく出た `??` の行（追跡外のファイル）だけを、1つずつ `rm -- '〈パス〉'` で消す。フォルダごと消さない。
   - 無視されたファイル（.env・開発用のデータベース・無視された設計書や報告など）、起動の前からあったファイル、追跡中のファイルには触れない。`git clean` を使わない。
   - パスが `"` で始まるか `'` を含むとき、追跡中のファイルが変わったとき、消してよいか分からないときは、消さず・戻さず、報告に書く。

## サインイン

- サインインは、リポジトリの seed や例の設定にある試しの値だけを使う。
- 本物のアカウントが要る流れと、秘密（トークン・.env の値・個人の情報）が画面に出る流れは録らない。報告に理由を書く（秘密そのものは書かない）。

## GIF の置き場所

- 拡張は GIF をブラウザのダウンロード先に書き出す。ダウンロード先では、決めた名前（`〈ID〉-〈流れの名前〉.gif`）ちょうどのものと、ブラウザが付けた「 (数字)」つきの名前（`〈ID〉-〈流れの名前〉 (1).gif` など）の両方を、印より新しいものだけ探す（録り始めより新しいものだけ。印は手順3の時刻）。2つ以上当たれば移さず、報告に書く。
- ブラウザが同じ名前で2回目に書き出したときの名前の形は、実機でまだ確かめていない（上の「 (数字)」つきは想定）。見つからなければ、ダウンロード先の新しいファイルの名前を会話で見て、報告に書く。
- 1つに決まったら、`orca-flow/captures/〈ID〉/` に `〈流れの名前〉.gif` の名前で移す（フォルダがなければ作る）。
- 見つからなければ、報告に「録れなかった：GIF が見つからない」と書いて進む。
- 録ったファイルを、リポジトリの中に置かない。コミットもしない。

## 大きさ

- GIF が 20 MiB（Notion のファイルの上限）を超えたら、画質を下げて1回だけ書き出し直す。
- それでも超えたら、そのファイルは置かず、報告に「録れなかった：20 MiB を超えた」と書く。

## 報告に書くこと

報告に「画面の記録」の節を書く。流れごとに、録れたか、録れなかった理由を1行で書く。手元のパスと Notion の URL は書かない。
