# E2E の録画（run が読む）

画面の動きを変えるブランチで、E2E のタスクが変わった動きを「前」と「後」で録る。録るのは、E2E の道具の録画で、テストを1本ずつ前の画面（ブランチの分かれ目のアプリ）と後の画面（ブランチのプレビュー）に流す形。前と後がそろった録画は、統括役の `/orca-flow:push` が PR の本文に載せる（PR の作成の案に添付し、PR がもうあれば本文の録画の節を直す案にする。人が send の前に録画を開いて見てから送る）。タスク長は録画をリポジトリに置かず、報告にも貼らない。PR の本文に載るので、秘密の流れを録らない決まり（下の「録る時期」）を必ず守る。

## 録る時期

- `skills/run/e2e.md` の `orca-flow e2e 〈ID〉` が通ったあと、報告を書く前に録る（テストを直して流し直したら、録り直す）。
- 録らない場合：伴う記録に録画の設定（`capture`）がないとき。設定の録画のコマンドがアプリごとで、`--companion` で渡したアプリの分が1つもないときも、記録に `capture` が写らず同じ扱いになる（設定にあっても録らない）。見分け方は、手順の最初の `--capture` が終了コード2で、標準エラーに「伴う記録に capture がありません」の文が出たとき（E2E を流し直さないよう、確かめだけに `e2e` を流さない）。報告に「録画の設定がないので録らなかった」と一言書く。
- 秘密の流れは録らない。本物のアカウントやトークンが画面に出るテストは、流れの候補から外す（`skills/run/screen-capture.md` の決まりと同じ）。外した流れは、報告に理由を書く。

## 流れの選び方

1. 足した・直したテストから、変わった動きを見せる流れを1〜3本選ぶ。長い流れより、動きの変化が1つ見える短いテストを選ぶ。
2. 流れごとに名前を付ける。頭は英小文字か数字で、英小文字・数字・`-` の40文字まで（例：`add-item`、`edit-title`）。
3. 1本の流れは、テスト1本に絞る。録画が0個や2個以上になると置かれないので、テストの指定（`--` のあと）で1本に絞る。

## 録る手順

1. 前の録画を消す：`orca-flow e2e 〈ID〉 --capture-clear`。
2. 流れごとに流す：`orca-flow e2e 〈ID〉 --capture 〈流れ〉 -- 〈テストの指定〉`。アプリが2つ以上の組では `--app 〈名前〉` も付ける。`--app` には、変わった動きを見せるアプリのうち、録画のコマンドのあるアプリを選ぶ（録画のコマンドがアプリごとのとき、キーのないアプリでは録れない）。
3. 終了コードで分ける。
   - 0：前と後の録画が置かれた。次の流れへ進む。
   - 2（「capture がありません」の文）：録画の設定がないか、アプリごとの録画のコマンドに `--companion` で渡したアプリの分がないので、残りの流れも録らずに手順を抜ける（`--capture-clear` は設定がなくても0で終わるので、これでは見分けられない）。報告に「録画の設定がないので録らなかった」と書く。
   - 2（前の画面が立っていない）：理由を読み、人に親のタブで `workspace --preview 〈ブランチ名〉 --base` を頼む（`orca-flow status question` にして伝える）。〈ブランチ名〉はこのタスクのブランチ名（worktree で `git branch --show-current`。組は全部の子で同じ ID と短い名前で始めるので、組のブランチ名と同じ）。ID で頼まない（番号だけ同じ別のアプリのブランチがあると、CLI が止まるため）。頼んだら、`orca-flow e2e 〈ID〉 --wait --base` を背景で流して待ち、0で終わったら流し直す。待つ間はほかの確かめを進める。`--wait --base` が2で終わったときは、理由を添えて人に聞く。1で終わったときは、標準エラーの文を人に伝えて止まる。前の画面の起動が終了コード2で止まる理由（設定の固定の URL でポートがぶつかる）なら、録れなかった理由として報告に書く。
   - 1（「capture.command に 〈名前〉 の分がありません」の文）：`--app` に選んだアプリに録画のコマンドがない。テストは直さず、文の末に並ぶアプリから変わった動きを見せるものを選び直して流し直す。並ぶアプリのどれも変わった動きを見せないなら、録れなかった理由として報告に書き、先へ進む。
   - 1（落ちた）：標準エラーの最後の数行を読む。後の画面で落ちたなら、テストを直して流し直す（前後とも置かれていない）。録画が0個・2個以上・大きすぎるときは、テストを1本に絞るか、録画の設定の見直しを人に聞く。直しても録れなければ、録れなかった理由として報告に書き、先へ進む。
4. 全部録り終えたら（録れなかった流れがあっても）、人に親のタブで `workspace --preview 〈ブランチ名〉 --base --stop` を頼み、前の画面を止める。
5. 前の画面で新しい動きのテストが落ちても、録画があれば置かれる。落ちたところまでが「前の動き」になるので、前で落ちたこと自体は直さない。

## 守ること

- 録画はリポジトリに置かない・コミットしない。置き場は `e2e` が決める（アプリのリポジトリの git の共通ディレクトリの下）。
- ターミナルと E2E の出力は読まず、報告にもカードにも写さない。標準エラーの数行も、秘密のありそうな値を書かない。
- テストを消したり弱めたりして録らない。録画のためにテストの中身を変えない。
- 報告には、流れごとに「録れた」か「録れなかった（理由）」を1行ずつ書く。
