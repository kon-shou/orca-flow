# 仕様のページの前の形（読み方）

`page-format.md` の「形の見分け」で前の形と決まったとき（ステップと組の形か、「何が変わるか」の見出しも「親のページ：」で始まるつながりの行もないページ）にだけ読む。前の形は、ステップと組の形、1ページの形、土台のページと単位のページの形、上の所のない古い形の4つ。どれも今あるページなので、今までどおり読み、書き換えて新しい形（ブランチの形の親のページとタスクのページ）にはしない。新しく作るページは、この文書でなく `page-format.md` に従う。ステップと組の形は、次の「ステップと組の形」の節で読む。ほかの3つは、その節の後ろのとおり。

前の形は、仕様のページを1ページのまま上（人向け）と下（細部。AI 向け）に分けたもの。人が読んで判断しやすいことと、AI がもれなく読むことは別の目的なので、上は人の言葉、下は今の ADR の中身にする。

この文書で「上の所のある1ページ」と呼ぶのは、前の形のうち上の所（人向けの所）のあるページのこと。「新しい形」はブランチの形の親のページとタスクのページだけを指し、この文書の形には使わない。「古い形」は、上の所のないページのこと。

## ステップと組の形

ブランチの形の前に作った、親のページとタスクのページの形。親に見出し「タスク」（と「何が変わるか」）があり、タスクのページのつながりの行が「親のページ：〈リンク〉 ／ このページはタスク〈番号〉」のもの。今あるページなので、このとおりに読み、書き換えてブランチの形にはしない（人の直しを落としうるため）。

- 親の並び：見分けの印の行・読み方の行・何が変わるか・分け方・タスク・（契約があれば）同時に作るタスクの間で使い合うもの・（組があれば）組の進め方・決めてほしいこと・区切りの線と細部・出典。タスクのページの並びは、印の行・つながりの行・要点・決めてほしいこと・細部・出典。
- タスク：ステップごとの小見出し「ステップ〈番号〉（〈何が入ったら〉同時に）」の下に、太字の行「〈番号〉. 〈タスク名〉」（タスクのページへのリンク）と概要、「待つもの：… ／ 大きさ：… ／ 状態：」の行がある。ステップが1つだけなら小見出しはない。待つものは「タスク〈番号〉」か「なし」。番号はステップの順に親全体で通しで振られている。
- 入れる順：「入れる順：タスク〈番号〉のあと」の行。待つものとは別で、`merged` には渡さない。
- 組：ワークスペースの道で、タスクに「リポジトリ：〈名前〉」の行と、組があるタスクに「組：組A」の行がある。組の2つは同じステップに置かれ、待つものはそれぞれ自分の（組の外の）依存だけを書く。組の相手は待つものに書かれていない。組の正は親の細部の「組ごとの決定」（見出しに「組A（slug：〈slug〉）」）で、タスクのページの1項目にも同じ slug がある。タスクの「組：」の行と、タスクの下の「組の進め方」の節（組ごとの入るタスク・順の各段・効く質問）は、その人向けの写しとして読む。人が行か節を直したら、反映で細部に合わせる。組の決まりに外れるときは、細部を直さず人に聞く。
- 状態と ID：親のタスクの「状態：」の行（「開始済み 〈ID〉」。ワークスペースの道では「開始済み 〈名前〉:〈ID〉」）だけにある。タスクのページにはない。書き場所は「〈番号〉. 〈タスク名〉」の行で選ぶ。
- 始め方：「待つもの：タスク〈番号〉」を、親のその番号の状態の行の ID に解いて、今の ID の形の確かめと `merged` にかける。状態の行にまだ ID がなければ、入っていないとして始めない。組の片方の待つものが入っていなければ、組の両方とも始めない。ワークスペースの道では、依存先のリポジトリが別なら `--depends` にも `--cross-depends` にも渡さず、親の状態の行の `〈名前〉:〈ID〉` で持つ（`workspace.md` の「またぐ依存の渡し方」のとおり。`--cross-depends` に渡すのは同じ組の共通への分だけで、組の外のほかのリポジトリの入った待つ先は渡さない）。
- 始める前の守り：`guards.md` の手順10の、ブランチの形の親とタスクのページに足した守りが、ステップと組の形にも同じに効く。タスクのページの URL からの親のたどり方・たどった親の確かめ・親とタスクのページが互いを指すかの確かめ（番号で比べる。ワークスペースの道ではリポジトリも）・依頼のファイルの「仕様」の URL はそのタスクのページ・読み直しと反映・質問の答えの読み方を、ブランチをタスクに、見出し「ブランチ」を見出し「タスク」に読み替えて守る（読み替えは `guards.md` のとおり）。
- 組の始め方・版上げ：組は今までどおり `workspace.md` の「ひとまとまりで始める」で始める（共通を含むブランチと同じ。組を「共通を含むブランチ」と読み替える）。
- 戻し：タスクのページを直し、親はそのタスクの概要だけを直してよい（状態の行は変えない）。親の細部・組の進め方・質問は直さず、人に渡す。ほかのタスクのページに届く違いも直さず、人に渡す。
- 見分け：親は見出し「タスク」と「何が変わるか」があり見出し「ブランチ」がないもの。タスクのページは「このページはタスク〈番号〉」があるもの。

## ページの並び

上から次の順に置く。3〜8（要点から出典まで）の見出しの名前はこのとおりにする。1・2（印の行・読み方の行）は見出しのない地の文で置く。

1. 見分けの印の行
2. 読み方の行
3. 要点
4. 決めてほしいこと
5. タスクの一覧
6. 組の進め方（組がなければ置かない）
7. 区切りの線と、細部（AI 向け）

## 見分けの印の行

- 本文の先頭に、地の文の一行で置く。書くのは新しい印「要件から自動で作った仕様のページ」。
- 前の印「orca-flow の intake が作った仕様のページ」も印とみなす。前の印を書き換えない。
- Notion に書く文には orca-flow の語を入れない。

## 読み方の行

- 印の次に1行だけ置く。質問は選ぶものにチェックを入れること、直すのは上の所でよく細部は自動で合わせること、開始済みの項目は上を直してもそのタスクには届かないことを書く。
- 例：

> 質問は、選ぶものにチェックを入れてください。直すのはこの上の所だけでよく、下の細部は自動で合わせます。「開始済み」の項目は、ここを直してもそのタスクには届きません。

## 要点

- 使う人から見て何が変わるか、タスクの数と順、質問の数（始める前に要るもの）を、数行で書く。
- 関数の名前やコードの行は書かない。
- 上の所は人の言葉で書き、初めて出る言葉はその場で短く説明する。
- 組があるときは、「組」（いっしょに進めるひとまとまり）の短い説明を、ページで最初に出る所（ふつうはここ）に1回だけ書く。ほかの所では説明を繰り返さない。

## 決めてほしいこと

- 質問ごとに1つの吹き出し（コールアウト）に入れる。質問がなければ「なし」とだけ書く。
- 吹き出しには、問い・いつまでに要るか・効く所（どのタスクか）・おすすめと理由1つ・選択肢のチェックボックス・「答え・補足：」の行を書く。おすすめの選択肢には印をつける。
- 選択肢のチェックボックスの下に、「これからも同じにする（後の要件にも効かせる）」のチェックボックスを1つ足す。このチェックは選択肢と分けて置き、答えのチェックの数に数えない。
- 質問の番号は1から振る。細部から質問を指すときは「決めてほしいこと〈番号〉」と書く。
- 決めてほしいことは上のここに置き、ページの末尾に別に足さない。
- 例：

> 問い：通知の送り先は、メールだけにしますか。
> いつまでに要るか：最初のタスクを始める前
> 効く所：タスク2
> おすすめ：メールだけ（理由：送り先を足すのは後からでも小さな変更で済む）
>
> - [ ] メールだけ（おすすめ）
> - [ ] メールとチャット
>
> - [ ] これからも同じにする（後の要件にも効かせる）
>
> 答え・補足：

## タスクの一覧

- 表にする。列は番号・タスク名・何ができるようになるか・依存・見込みの大きさ・状態。ワークスペースの道ではリポジトリの列を足す。
- 組があるときだけ（1つ以上あるとき）、リポジトリの列の次に「組」の列を足す。同じ組のタスクに同じ組の名前を入れ、組でないタスクは空にする。組がなければ列を足さない。組の名前は「組A」「組B」…（出た順）にする。番号のタスクや質問と取り違えない名前にする。
- 組のタスクは番号を続けて並べ、共通を先にする。
- 依存の欄に組の相手を書かない（組の列で示す）。組の外の依存は今までどおり書く。
- 表の欄は見出しの名前で読み、位置で読まない。
- 見込みの大きさの欄は「中（コード 130〜200・テスト 100〜180・全体 230〜380）」の形で、コード・テスト・全体の行を書く。移すだけの行があれば「移すだけ 約〈行〉」を添える。目安（splitting.md の基準3）を超える項目には「目安超え」を添える。
- 見込みの大きさの列の中身の形は、手順10と反映で確かめない。「小」「中」だけの今の形の列も、そのまま読み、書き換えない。
- 状態の欄は、始める前は空にする。始めたら「開始済み 〈ID〉」と書く（ワークスペースの道では「開始済み 〈名前〉:〈ID〉」）。
- 例：

> | 番号 | タスク名   | 何ができるようになるか       | 依存 | 見込みの大きさ                                        | 状態 |
> | ---- | ---------- | ---------------------------- | ---- | ----------------------------------------------------- | ---- |
> | 1    | 通知の下地 | 通知の送り先を設定できる     | なし | 小（コード 40〜60・テスト 30〜50・全体 70〜110）      |      |
> | 2    | 通知を送る | 設定した送り先に知らせが届く | 1    | 中（コード 130〜200・テスト 100〜180・全体 230〜380） |      |

## 組の進め方

- 組があるときだけ、タスクの一覧の下に置く。組がなければ節を置かない。
- 組ごとに「組A：」の行で分け、その下に、入るタスク（番号）・順の各段・この組に効く質問の番号（なければ「なし」）を書く。
- 順の各段は、始める → 共通の PR をマージ → 共通の版を出す（人が行う）→ 見張りがアプリのタスク長を起こして正式な版に上げる → アプリの PR をマージ。人が行う段の末尾に「（人が行う）」を付ける。共通の項目には、共通を使うアプリの項目が必ず組になる（要件で変えないアプリは版上げだけの項目）。
- 「2つは同時に始まり、片方だけを待たせられない。質問の『待つ』は組の両方に効く」を書く。組の両方に効く質問は、吹き出しの効く所に組の名前（組A など）も書く。
- この節には状態も ID も書かない（ID は一覧の状態の欄だけ）。
- 組の正は細部の組（タスクへの分け方）で、この列と節は人向けの写しとする。組の列がない上の所のある1ページ（今あるページ）も、細部から組を読む。列や節を後から足して書き換えない。
- 人が組の列か組の進め方を直したら、今の反映で細部に合わせる。組の決まり（組の中で1つのリポジトリの項目は1つ、など）に外れるときは、細部を直さず人に聞く。

## ID を書く所

- ID は一覧の表の状態の欄だけに書く。細部の見出しの横には書かない（2か所に書くとずれるため）。
- 「項目の横」の ID は、上の所のある1ページではこの状態の欄を指す。

## 細部（AI 向け）

- 上の所と区切りの線で分け、見出し「細部（AI 向け）」を置く。
- 中身は、ADR の4つの節（状況・決定・結果・捨てた案）と、タスクへの分け方。今の決まり（guards.md の手順6）の中身をそのまま置く。
- 節ごとに折りたたみ（トグル）にする。
- 質問を指すときは「決めてほしいこと〈番号〉」と書き、質問の文は写さない。
- 組があるときは、タスクへの分け方で「組A（slug：〈slug〉）」と書き、上の組の名前と細部の組の slug をつなぐ。

## 出典

- 読んだイシューとチケットの出典を、最後に置く。

## 複数のページの形

分け方の基準（`splitting.md`）で単位が2つ以上になったときだけ使う。単位が1つなら、ここは読まず、上の1ページの形のままにする。単位は、ほかの単位を待たずに作って入れられるタスクのまとまり。ページは、土台のページ1つと、単位ごとのページになる。どれもチケットの「自動で追記」の節の下の子ページで、見分けの印の行は上の「見分けの印の行」のとおり全部に入れる。Notion に書く文に orca-flow の語を入れない決まりは、土台のページにも単位のページにもそのまま効く。

- 単位は「単位1」「単位2」…と番号で呼ぶ。単位のタスクの番号は、そのページの中で1から振る。
- 依存の欄に書けるのは、同じページのタスクと「土台のタスク〈番号〉」だけ（〈番号〉は土台のページの下地のタスクの一覧の番号）。ほかの単位のタスクは書かない（単位どうしは依存を持たない）。
- 入れる順があるときだけ、タスクの一覧に「入れる順」の列を足す。値は「単位〈番号〉のタスク〈番号〉のあと」（同じ単位の中は依存で積むので、別の単位のタスクだけを書く）で、ない項目は空にする。入れる順は依存の欄には書かない（`merged` にも渡さない）。始めてよいかは、下の「始め方（前の形）」と `guards.md` のとおり（前の項目が開始済みか入ったときだけ始める）。ない列は足さない。
- 状態の欄と ID は上の決まりのまま、そのタスクがあるページの表の状態の欄だけに書く。

### 土台のページ

上から次の順に置く。印の行と読み方の行は、1ページの形と同じ。見出しの名前はこのとおりにする。

1. 要点：単位の数、単位は同時に始まること、待つのは下地のタスクだけであること。使う人から見て何が変わるか、質問の数も数行で書く。
2. 決めてほしいこと：2つ以上の単位に効く質問を、1ページの形と同じ吹き出しで置く。1つの単位だけに効く質問は、その単位のページに置く。なければ「なし」。
3. 単位の一覧：表。列は単位（「単位1」…）・名前・何ができるようになるか・待つもの（土台のタスク〈番号〉か「なし」）・単位のページへのリンク。
4. 契約：単位の間で使い合うものの名前・形・呼び方。ないときは「なし」。
5. 下地のタスクの一覧：1ページの形のタスクの一覧と同じ列（番号・タスク名・何ができるようになるか・依存・見込みの大きさ・状態）。ないときは「なし」。
6. 細部（AI 向け）：区切りの線で分け、全体の状況と、分け方の捨てた案を置く。下地のタスクがあれば、その分の「タスクへの分け方」（1項目に書くことは1ページのときと同じ。slug・作るもの・書き込みそうな場所を含む）もここに置く。単位ごとの細部は単位のページに置く。

### 単位のページ

今の1ページの形（印の行・読み方の行・要点・決めてほしいこと・タスクの一覧・組の進め方・細部・出典）に、読み方の行の次の「つながり」の1行を足す。

- 書き方：「つながり：チケット〈リンク〉・土台〈リンク〉・ほかの単位〈単位の番号とリンク〉…」。地の文の一行にする。
- この単位のページには、この単位のタスクだけを書く。この単位だけに効く質問は、決めてほしいことに置く。
- 組があれば、1つの単位の中に置く。

### 複数のページと1ページの見分け

- 上の所のある形のうち複数のページかどうかは、つながりの行があるか、見出し「単位の一覧」があるかで見分ける（単位のページにはつながりの行が、土台のページには「単位の一覧」がある）。
- つながりの行がない（かつ「単位の一覧」もない）ページは、今までどおりの1ページの形として読む。書き換えて複数のページの形にはしない。
- 土台のページは、単位のページの一覧を持つだけで、単位のタスクは持たない。

### 始め方（前の形）

複数のページ（土台のページと単位のページ）を始めるときは、`guards.md` の手順10の決まりに、次を足して守る。

- 始める範囲：渡された URL が土台のページなら、土台の下地のタスクと各単位のタスクの全部を始める項目にする。単位のページの URL なら、その単位のタスクと、それが待つ土台の下地のタスクだけを始める項目にする。土台とほかの単位のページは、状態の欄を読むためだけに読み、そこにある項目は始めない。打ち直しも同じ（打ち直しの URL が土台の URL なら全部のページ、単位の URL ならその単位だけを続ける。単位のページを読んだときも、土台のページと契約を読む）。
- 「土台のタスク〈番号〉」の依存は、土台のページの状態の欄の ID（下地のタスクの一覧の欄）で、入ったかを決める（その ID を集めて `merged` に渡す）。土台のタスクにまだ ID がなければ、入っていないとして始めない。ID の形の確かめは今の ID の決まりのまま。
- 入れる順のある項目（「入れる順」の列が「単位〈番号〉のタスク〈番号〉のあと」）は、前の項目が開始済みか入ったときだけ始める。前の項目の状態の欄に「開始済み 〈ID〉」があれば開始済み。入ったかを決めるため、前の項目の ID も `merged` の1回に含める。前の項目にまだ ID がなく、同じ回にも始めないなら、始めない。単位は同時に始まるので、同じ回で前の項目も後の項目も始めるときは、前の項目を先に始め、その new で出た ID を使って後の項目も同じ回に始めてよい（「よい」を待つ一覧には、前と後の両方を入れる）。前の項目がすでに入っていれば order は流さない。両方が作業中なら、後の項目の new のあとに入れる順を CLI に足す（ID は前の項目の状態の欄と new の出力から読む。足し方とワークスペースの道で流さないことは `guards.md` の手順10のとおり）。
- 入れる順の前の項目がほかの単位のページにあるときは、今のページのつながりの行（か土台の単位の一覧）のリンクからそのページをたどり、状態の欄を読む。
- 「よい」を待つ一覧は、全部のページの始める項目をまとめて示す。
- 組の2つの「待つもの」（組のタスクの依存の欄）：組の2つは同時に始まる。組の片方の待つもの（下地のタスクなど）が入っていなければ、組の両方とも始めない。
- 依頼のファイルへの写し：単位のページの項目には、その単位のページの中身（その項目の全文・決めてほしいことと答え・3つの URL）に加えて、土台の契約・土台の質問と答え・入れる順を文で写す。URL はイシュー・チケット・そのタスクのページの3つのままにし、土台の URL は写さない（仕様のページへの追従が、印のあるページを2つ見つけて迷うため）。土台の下地のタスクの依頼のファイルへは、土台のページの中身に加えて、その項目の全文（土台の細部のタスクへの分け方の、その下地のタスクの分）を写し、単位のページの URL は写さない。
- ID の書き込み：new が通るたびに、そのタスクがあるページの表の状態の欄に「開始済み 〈ID〉」と書く（ワークスペースの道では「開始済み 〈名前〉:〈ID〉」）。
- 1ページの形のワークスペースの道：依存の欄は、同じリポジトリの依存も含めて `〈名前〉:〈ID〉` の形で書く。単位が2つ以上のときも、単位のページの依存の欄は、同じ単位の中の依存は `〈名前〉:〈ID〉` で、土台の下地のタスクへの依存は「土台のタスク〈番号〉」で書く。土台のタスクへの依存は、手順10で、土台のページの状態の欄の `〈名前〉:〈ID〉` に解いてから、今までの名前と ID の確かめにかける。状態の欄にまだ ID がなければ、入っていないとして始めない。組の相手は依存の欄に書かず、組の列で示す。またぐ依存の照合（依存先の名前をページの欄と比べる）では、組の相手（同じ組の共通）は依存の欄でなく組から読み、ページの欄との照合は組の外のまたぐ依存だけに当てる（組の正は細部のタスクへの分け方で、上の所の組の列はその写し）。
- 共通に置く下地（ワークスペースの道）：共通（共有のリポジトリ）に置く下地は土台に置かない。共通の項目は使うアプリと必ず組にし、組は1つの単位の中に置くので、共通に置く下地は、それを使うアプリの項目と一緒に1つの単位にまとめる。土台の下地のタスクは、アプリのリポジトリの中だけに置く。

## 作れないときの代わり

- 道具が吹き出し・チェックボックス・折りたたみ・表を作れないときは、同じ並びを見出しと箇条書きで書く。子ページを作れず下書きを人に示すときも同じ。
- チェックの代わりに「答え：」の行にする。「これからも同じにする」のチェックの代わりは、「これからも：」の行（「同じにする」か空）にする。この行も答えの数に数えない。
- 表がないので、状態は各項目の箇条書きに「状態：開始済み 〈ID〉」の行で書く。
- 組のタスクの項目には「組：組A」の行を足す。組の進め方は、見出しと箇条書きで同じ中身を書く。

## 古い形のページ

- 上の所のない今までの形（本文が ADR の節だけで、ID が見出しの横にあるもの）も、そのまま読めて戻せるようにする。
- 上の所のある1ページか古い形かは、「タスクの一覧」の表か「細部（AI 向け）」の見出しがあれば上の所のある1ページ、どちらもなければ古い形とする。
- 古い形では、今までどおり項目の横（見出しの横など）の ID を読む。書き換えて新しい形にはしない。
