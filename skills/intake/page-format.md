# 仕様のページの形

intake の手順6で下書きを書くときと、手順8の子ページを作るときに読む。仕様のページを、1ページのまま上（人向け）と下（細部。AI 向け）に分ける。人が読んで判断しやすいことと、AI がもれなく読むことは別の目的なので、上は人の言葉、下は今の ADR の中身にする。

## ページの並び

上から次の順に置く。3〜8（要点から出典まで）の見出しの名前はこのとおりにする。1・2（印の行・読み方の行）は見出しのない地の文で置く。

1. 見分けの印の行
2. 読み方の行
3. 要点
4. 決めてほしいこと
5. タスクの一覧
6. 組の進め方（組がなければ置かない）
7. 区切りの線と、細部（AI 向け）
8. 出典（統合が足す「実装で変わったこと」「実装後の画面」は、その後ろに今までどおり足される）

## 見分けの印の行

- 本文の先頭に、地の文の一行で置く。書くのは新しい印「要件から自動で作った仕様のページ」。
- 前の印「orca-flow の intake が作った仕様のページ」も印とみなす。前の印を書き換えない。
- Notion に書く文には orca-flow の語を入れない。

## 読み方の行

- 印の次に1行だけ置く。質問は選ぶものにチェックを入れること、直すのは上の所でよく細部は自動で合わせること、開始済みの項目は上を直してもそのタスクには届かないことを書く。
- 例：

> 質問は、選ぶものにチェックを入れてください。直すのはこの上の所だけでよく、下の細部は自動で合わせます。「開始済み」の項目は、ここを直してもそのタスクには届きません。

## 要点

- 使う人から見て何が変わるか、タスクの数と順、質問の数（始める前に要るもの）を、数行で書く。
- 関数の名前やコードの行は書かない。
- 上の所は人の言葉で書き、初めて出る言葉はその場で短く説明する。
- 組があるときは、「組」（いっしょに進めるひとまとまり）の短い説明を、ページで最初に出る所（ふつうはここ）に1回だけ書く。ほかの所では説明を繰り返さない。

## 決めてほしいこと

- 質問ごとに1つの吹き出し（コールアウト）に入れる。質問がなければ「なし」とだけ書く。
- 吹き出しには、問い・いつまでに要るか・効く所（どのタスクか）・おすすめと理由1つ・選択肢のチェックボックス・「答え・補足：」の行を書く。おすすめの選択肢には印をつける。
- 選択肢のチェックボックスの下に、「これからも同じにする（後の要件にも効かせる）」のチェックボックスを1つ足す。このチェックは選択肢と分けて置き、答えのチェックの数に数えない。
- 質問の番号は1から振る。細部から質問を指すときは「決めてほしいこと〈番号〉」と書く。
- 決めてほしいことは上のここに置き、ページの末尾に別に足さない。
- 例：

> 問い：通知の送り先は、メールだけにしますか。
> いつまでに要るか：最初のタスクを始める前
> 効く所：タスク2
> おすすめ：メールだけ（理由：送り先を足すのは後からでも小さな変更で済む）
>
> - [ ] メールだけ（おすすめ）
> - [ ] メールとチャット
>
> - [ ] これからも同じにする（後の要件にも効かせる）
>
> 答え・補足：

## タスクの一覧

- 表にする。列は番号・タスク名・何ができるようになるか・依存・見込みの大きさ・状態。ワークスペースの道ではリポジトリの列を足す。
- 組があるときだけ（1つ以上あるとき）、リポジトリの列の次に「組」の列を足す。同じ組のタスクに同じ組の名前を入れ、組でないタスクは空にする。組がなければ列を足さない。組の名前は「組A」「組B」…（出た順）にする。番号のタスクや質問と取り違えない名前にする。
- 組のタスクは番号を続けて並べ、共通を先にする。
- 依存の欄に組の相手を書かない（組の列で示す）。組の外の依存は今までどおり書く。
- 表の欄は見出しの名前で読み、位置で読まない。
- 状態の欄は、始める前は空にする。始めたら「開始済み 〈ID〉」と書く（ワークスペースの道では「開始済み 〈名前〉:〈ID〉」）。
- 例：

> | 番号 | タスク名   | 何ができるようになるか       | 依存 | 見込みの大きさ | 状態 |
> | ---- | ---------- | ---------------------------- | ---- | -------------- | ---- |
> | 1    | 通知の下地 | 通知の送り先を設定できる     | なし | 小             |      |
> | 2    | 通知を送る | 設定した送り先に知らせが届く | 1    | 中             |      |

## 組の進め方

- 組があるときだけ、タスクの一覧の下に置く。組がなければ節を置かない。
- 組ごとに「組A：」の行で分け、その下に、入るタスク（番号）・順の各段・この組に効く質問の番号（なければ「なし」）を書く。
- 順の各段は、始める → 共通の PR をマージ → 共通の版を出す → アプリを正式な版に戻す → アプリの PR をマージ。人が行う段の末尾に「（人が行う）」を付ける。
- 「2つは同時に始まり、片方だけを待たせられない。質問の『待つ』は組の両方に効く」を書く。組の両方に効く質問は、吹き出しの効く所に組の名前（組A など）も書く。
- この節には状態も ID も書かない（ID は一覧の状態の欄だけ）。
- 組の正は細部の組（タスクへの分け方）で、この列と節は人向けの写しとする。組の列がない新しい形のページ（今あるページ）も、細部から組を読む。列や節を後から足して書き換えない。
- 人が組の列か組の進め方を直したら、今の反映で細部に合わせる。組の決まり（組の中で1つのリポジトリの項目は1つ、など）に外れるときは、細部を直さず人に聞く。

## ID を書く所

- ID は一覧の表の状態の欄だけに書く。細部の見出しの横には書かない（2か所に書くとずれるため）。
- 「項目の横」の ID は、新しい形ではこの状態の欄を指す。

## 細部（AI 向け）

- 上の所と区切りの線で分け、見出し「細部（AI 向け）」を置く。
- 中身は、ADR の4つの節（状況・決定・結果・捨てた案）と、タスクへの分け方。今の決まり（guards.md の手順6）の中身をそのまま置く。
- 節ごとに折りたたみ（トグル）にする。
- 質問を指すときは「決めてほしいこと〈番号〉」と書き、質問の文は写さない。
- 組があるときは、タスクへの分け方で「組A（slug：〈slug〉）」と書き、上の組の名前と細部の組の slug をつなぐ。

## 出典

- 読んだイシューとチケットの出典を、最後に置く。

## 作れないときの代わり

- 道具が吹き出し・チェックボックス・折りたたみ・表を作れないときは、同じ並びを見出しと箇条書きで書く。子ページを作れず下書きを人に示すときも同じ。
- チェックの代わりに「答え：」の行にする。「これからも同じにする」のチェックの代わりは、「これからも：」の行（「同じにする」か空）にする。この行も答えの数に数えない。
- 表がないので、状態は各項目の箇条書きに「状態：開始済み 〈ID〉」の行で書く。
- 組のタスクの項目には「組：組A」の行を足す。組の進め方は、見出しと箇条書きで同じ中身を書く。

## 古い形のページ

- 上の所のない今までの形（本文が ADR の節だけで、ID が見出しの横にあるもの）も、そのまま読めて戻せるようにする。
- 新しい形か古い形かは、「タスクの一覧」の表か「細部（AI 向け）」の見出しがあれば新しい形、どちらもなければ古い形とする。
- 古い形では、今までどおり項目の横（見出しの横など）の ID を読む。書き換えて新しい形にはしない。
