あなたは統括役として、タスク $0 の設計を承認する。人間が設計書を読んで、よいと判断したあとに呼ばれている。

CLI は `orca-flow` で呼ぶ（プラグインの bin が PATH に入っている）。見つからなければ `"${CLAUDE_PLUGIN_ROOT}/bin/orca-flow"` で呼ぶ。終了コードは 0＝成功、1＝確認に落ちた・失敗、2＝人間か統括役の作業が先に要る、3＝git の競合。

## 手順

1. `orca-flow config --json` で設定を読む（tasksDir・verify・integratorName）。`orca-flow active` で $0 のブランチを調べる。
2. タスクのブランチの設計書を読む：`git show 〈ブランチ〉:〈tasksDir〉/$0.md`。
3. 「main への事前変更」を見る。
   - 「なし」なら：`orca-flow approve $0` を流す。
   - 変更があれば：まず `git log main --first-parent --format='%s%x09%H'` で、main の first-parent のコミット（マージで入ったタスクのコミットは除く）を、件名を行の頭に出して探す。正規表現 `^〈integratorName〉: $0 の事前変更` は、件名（行の頭）に当てる。当たるものが2つ以上なら、いちばん上（いちばん新しい）ものを使う。
     - 見つかったら、「〈integratorName〉: $0 の事前変更」のコミットがすでにある。本文は `git show -s --format=%b 〈ハッシュ〉` で読み、その「設計書：〈blob〉」の行と、今の設計書の blob（`git rev-parse 〈ブランチ〉:〈tasksDir〉/$0.md`）を比べる。
       - blob が同じなら、入れ直さず `orca-flow approve $0 --prechanges-done` を流す（手順4へ）。
       - blob が違えば、2つの blob（`git show 〈blob〉`）の「main への事前変更」の節を比べる。節が同じなら、入れ直さず `orca-flow approve $0 --prechanges-done` を流す（手順4へ）。
       - 節が違うか、本文に「設計書：」の行がない（古いコミット）なら、入れ直さず人間に、前の事前変更と今の事前変更の差を見せて、どうするか聞いてから進める。
       - 前の blob が `git show 〈blob〉` で読めない（gc など）とき、〈blob〉が16進の形でないときも、同じく入れ直さず人間に聞く。
     - 見つからなければ、統括役が main で行う。
     1. 書かれたとおりに共有のファイルを変える。書き方があいまいで決めきれないときは、人間に聞いてから行う。ロックファイルは手で直さず、パッケージマネージャーで作り直す。
     2. config の verify のコマンドを順に流し、すべて通ることを確かめる。落ちたら直す。直せなければ人間に伝えて止まる。
     3. 変えたファイルだけを `git add` し、`〈integratorName〉: $0 の事前変更（〈要点〉）` でコミットする。本文に「設計書：〈blob〉」の1行を入れる（〈blob〉は `git rev-parse 〈ブランチ〉:〈tasksDir〉/$0.md` の値）。
     4. `orca-flow approve $0 --prechanges-done` を流す。
4. 終了コードごとに次をする。
   - 0：人間に「$0 の実行を始めました。統合待ちになったら未読の印がつきます」と伝える。
   - 2：メッセージ（統括役の場所でない、事前変更が済んでいない、タスク長のターミナルが1つに決まらない、タスク長の入力欄に打ちかけがある、タスク長のターミナルが bash モードになっている、タスク長の入力欄を確かめられない、など）を人間に伝え、何をすればよいかを添えて止まる。標準エラーに「送れませんでした」が入るときは、CLI が出した送れなかった文と候補のタブ（題名とハンドル）をそのまま伝え、入力欄に打ちかけなら、その文を送るか消してもらい、直ったら下の流し直しをする。
   - 終了コード2で止まったあと（`--prechanges-done` で流していたときも、「なし」で流していたときも）：人間が原因（打ちかけ、bash モード、入力欄を確かめられない、など）を直したと言ったら、スキルを打ち直してもらわず、前と同じ引数で CLI を流し直す。`--prechanges-done` で流していたなら、事前変更はすでに main に入っているので入れ直さず、`orca-flow approve $0 --prechanges-done` を流し直す。「なし」なら `orca-flow approve $0` を流し直す。approve は送る直前にもう一度入力欄を確かめるので、rebase と進捗表のコミットのあとでも終了コード2になりうる。流し直せば続きから進む。
   - `orca-flow tell` を流して終了コード2が返ったとき（見つからない・1つに決まらない・打ちかけ・bash モード・入力欄を確かめられない）：CLI が出した送れなかった文と候補のタブを人間に伝えて止まる。
   - 3：rebase が競合した。`orca-flow tell $0 "git rebase をして競合を直し、spec-review に戻して"` を流し、人間に「$0 のタスク長に競合を直すよう伝えました。spec-review に戻ったら続けます」と伝えて止まる。人間が戻ったと言ったら、前と同じ引数で CLI を流し直す（`--prechanges-done` で流していたなら事前変更は入れ直さない）。
   - 1：メッセージ（設計書がコミットされていない、タスクの worktree に未コミットの変更がある、確認に落ちた、など）を人間に伝えて止まる。

## 守ること

- タスクの worktree の中のファイルを、統括役のタブから書き換えない。
- push はしない。
