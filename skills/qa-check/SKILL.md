description: orca-flow のタスクの QA 項目を、タスクのブランチのプレビューで AI がブラウザを動かして確かめる。事実の項目は判定し、目で見る項目は前と後の画面を撮って並べるだけにする。タスクのタブで人間が打つ。
argument-hint: "[ID]"

あなたはタスク $0 の QA 項目を、プレビューのブラウザで確かめる。人の QA の前に、事実の項目が通るかと、目で見る項目の前と後の画面をそろえて渡すのが役目。人がこのタスクのタブで打ったときだけ動く（run の中では流さない）。

CLI は `orca-flow` で呼ぶ（プラグインの bin が PATH に入っている）。`orca-flow` が PATH になければ止まり、人間に `/reload-plugins` を頼む。終了コードは 0＝成功、1＝確認に落ちた・失敗、2＝人間か統括役の作業が先に要る。

このスキルではコードを直さない。ファイルを書くのは、`--record` に渡す入力の JSON（リポジトリの外の一時ファイル）だけ。仕様のページ（Notion）を読み書きしない。

## 守ること

- URL は `orca-flow qa-check $0 --open` が preview の記録（`--base` なら前の画面の記録）から読んだものだけを使う。記録がない・答えないときに、本番・既定のホスト・ほかのタスクの URL など、ほかの URL で代わりに流さない。
- `orca goto` は、開いた URL と同じ origin（スキームとホストとポート）の下の URL だけにする。外のサイトへのリンクはたどらない。
- タブは `--open` が開いたタブだけを使い、`orca tab create` を直に流さない。`--open` はその回だけの分けた保存の区画（isolated の profile）でタブを開くので、人が自分のアカウントでサインインしたブラウザの状態が来ない。
- `orca snapshot`・`orca click`・`orca fill`・`orca goto`・`orca eval` は、いつも `--open` が出したページの ID を `--page 〈ページの ID〉` で渡して使う（ほかのタブを触らないため）。
- サインインは、リポジトリの seed や例の設定にある試しの値だけを使う（`${CLAUDE_PLUGIN_ROOT}/skills/run/screen-capture.md` の「サインイン」と同じ）。本物のアカウントや秘密（トークン・.env の値・個人の情報）が要る項目は、操作せず `unverified` にして理由を書く（秘密そのものは書かない）。
- `--open`（前の画面も）で開いた直後、自分がサインインする前の画面がサインイン済み（試しの値でないアカウント名・サインアウトのボタンなどが出ている）なら、そのタブで操作も撮影もしない。残りの項目を `unverified` にして理由を書き（アカウント名そのものは書かない）、手順8で残し、手順9の片づけを流してから人に伝える。
- 準備ができない項目（要るデータがない・機能スイッチが切れている・権限のある試しのアカウントがない）も `unverified` にして、要る準備を理由に書く。
- QA 項目や画面の中身を、決定の記録など公開に出るファイルに写さない。記録の置き場はリポジトリの外で、コミットしない。
- 手順4より後で途中で止まるとき（`--open` がまた2で止まる・`--record` を直せずに終わる など）も、手順9の片づけ（`orca-flow qa-check $0 --close` と、自分が立てたものだけの `--stop`）を流してから止まる。タブとプレビューを残したままにしない。
- `--open`（`--base` も、開き直しも）が終了コード1（区画を作れない・タブについた区画が違う・Orca の失敗 など）なら、出力を人に伝え、手順9の片づけを流してから止まる。ほかのタブや `orca tab create` で代わりに開かない。

## 手順

1. 依頼のファイルを読む：`git rev-parse --path-format=absolute --git-common-dir` の下の `orca-flow/requests/$0.md` を読み、「QA 項目」の行（「必須：」「できれば：」「必須（目で見る）：」「できれば（目で見る）：」で始まるもの）を集める。「QA の筋書き：」の下の行は集めない（複数のリポジトリをまたぐ動きで、組のプレビューで確かめるもの）。ファイルがない・項目がない（「なし」だけを含む）ときは、人に「QA 項目がない」と伝えて止まる。
2. 前の回を片づける：`orca-flow qa-check $0 --clear` を流す。
3. 分ける：項目ごとに `kind` を「事実」か「目で見る」に決める。
   - 印のある項目（「必須（目で見る）：」「できれば（目で見る）：」）は、印のとおり「目で見る」にする。
   - 印のない項目（「必須：」「できれば：」。印ができる前のページの形も同じ）は、期待する結果が画面の文字・値・出る出ない（ボタンが出ない・誤りの文が出る・保存される）で判定できれば「事実」、見た目の好み（そろい方・見やすさ・色・間隔）によれば「目で見る」にし、分けた理由を `reason` に書く。
   - `weight` は項目の頭の「必須」か「できれば」をそのまま使う。
4. 立てる：`orca-flow qa-check $0 --open --json` を流す。
   - 出たページの ID を「後のページの ID」として覚える。手順6・7で使う。
   - 終了コード2（preview の記録がない・答えない）なら、`orca-flow preview $0 --no-open` を流して立て、もう一度 `--open --json` を流す。`orca-flow preview` が終了コード1（URL が時間内に出ない・設定がない など）なら、出力を人に伝え、手順9の片づけを流してから止まる。それでも2なら、出力の理由と次の手を人に伝えて止まる（ほかの URL で流さない）。
   - 目で見る項目があれば、前の画面も同じに見る：`orca-flow qa-check $0 --open --base --json` が2なら `orca-flow preview $0 --base --no-open` を流して立て、もう一度流す。出たページの ID を「前のページの ID」として覚える。それでも立たなければ、前の画面なしで進み、目で見る項目の `reason` に「前の画面が立たなかった」と理由を書く。
   - 開いたら、操作の前に `orca snapshot --page 〈ページの ID〉` で、守ることのサインイン済みの画面でないかを見る。
   - このスキルで立てたもの（プレビューと前の画面）を覚えておく。最後に止めるのは、自分が立てたものだけ。
5. 前の画面を撮る（目で見る項目があり、前の画面が立ったとき）：前のページの ID（手順4の `orca-flow qa-check $0 --open --base --json` で出たもの）で、目で見る項目ごとに、後の画面と同じ操作をしてから `orca-flow qa-check $0 --shot 〈名前〉 --base` を流す。名前は項目ごとに決める英小文字・数字・ハイフンだけの短い名前（例：`settings-mail`）。ここではタブを閉じない（`--close` は後と前の両方のタブを閉じるので、手順9でまとめて流す）。
6. 後の画面で確かめる：後のページの ID（手順4の `orca-flow qa-check $0 --open --json` で出たもの）を `--page` に渡す。
   - 事実の項目：`orca snapshot --page 〈ページの ID〉` で画面を読み、`orca click`・`orca fill`・`orca goto` で項目の操作をして、期待する結果と比べる。合えば `pass`、合わなければ `fail` にして、何が出たかを `reason` に書く。通った・落ちたのどちらでも、比べた画面を `orca-flow qa-check $0 --shot 〈名前〉` で撮り、その名前を `after` に入れる。操作できない・判定できないときは `unverified` にして理由を書く。
   - 目で見る項目：手順5と同じ操作をして `orca-flow qa-check $0 --shot 〈名前〉` で撮る。前と後で同じ名前を使い、`before` と `after` に入れる。このスキルでは判定しないで `human` にする（見た目の正しさは人が決める）。
   - `--shot` が終了コード1なら、出力で見分ける（前の画面の `--shot 〈名前〉 --base` も同じ。前の画面のときは、ページの ID と URL を前の画面のもの（`--open --base --json` が出したもの）に読み替える）。
     - origin が違う（今のタブの origin が開いた origin と違う）：後の画面なら、その項目を `unverified` にして理由を書く。どちらの画面でも、`orca goto --page 〈ページの ID〉 --url 〈--open が出した URL〉` で開いた URL に戻ってから次の項目へ進む。
     - タブが読めない・ない（開き直しを案内された）：`orca-flow qa-check $0 --open --json`（前の画面なら `orca-flow qa-check $0 --open --base --json`）を流し直し、新しく出たページの ID をその後のページの ID にして、その項目の操作からやり直す。開き直すのは1つの項目につき1回までで、開き直したあとの `--shot` もまた1なら、後の画面ならその項目を `unverified` にして理由を書く。後の画面の開き直しが終了コード2なら、手順9の片づけを流してから止まる（前の画面の開き直しが2なら、手順4の「前の画面が立たない」と同じに前の画面なしで進む）。
     - それ以外（画像を読めない・Orca の失敗など）：後の画面なら、その項目を `unverified` にして出力の理由を書き、次の項目へ進む。同じ理由で続けて落ちるなら撮るのをやめ、残りの事実の項目は撮らずに判定を続け（`after` は `null`）、撮れない目で見る項目は `unverified` にして理由を書く。どの項目も入力から抜かない。撮るのをやめたあとに手順7で見つけた崩れは `notices` に入れず、撮るのをやめたことと理由と一緒に、手順10で文だけを人に伝える。
     - 前の画面の撮影がどの理由で落ちても、その目で見る項目は `human` のまま後の画面だけを撮り、前の画面を撮れなかった理由を `reason` に書く（`before` は `null`）。前の画面のことでスキルを止めない。
7. 崩れを見る：変わった画面（項目で開いた画面）で、`orca eval --page 〈ページの ID〉 --expression '〈JS の式〉'` を使い、横のはみ出し（`document.documentElement.scrollWidth` が `clientWidth` より大きい）と読めない画像（`img` で `complete` なのに `naturalWidth` が0）を調べる。見つけたら、その画面を `--shot` で撮り、文と撮った名前を `notices` に入れる。崩れで項目の結果は変えない。
8. 結果を残す：リポジトリの外の一時ファイル（`mktemp` で作る）に入力の JSON を書き、`orca-flow qa-check $0 --record --input 〈JSON のパス〉` を流す。
   - 形：`{ "items": [ … ], "notices": [ … ] }`。`items` の各要素は `text`（依頼のファイルの項目の文のまま）・`weight`（`必須` か `できれば`）・`kind`（`事実` か `目で見る`）・`result`（`pass`・`fail`・`unverified`・`human` のどれか）・`reason`・`before`（前の画面の撮った名前。なければ `null`）・`after`（後の画面の撮った名前。なければ `null`）。`notices` の各要素は `text`（見つけた崩れの文）と `shot`（撮った名前）。
   - `fail` と `unverified` は `reason` が必須。撮った名前は `--shot` で撮ったものだけを書く。
   - 終了コード1なら、出力の理由を読んで入力を直し、流し直す（判定は変えない）。書き終えたら一時ファイルを消す。
9. 片づける：`orca-flow qa-check $0 --close` を流す。手順4で自分が立てたものだけを止める（プレビューは `orca-flow preview $0 --stop`、前の画面は `orca-flow preview $0 --base --stop`）。人が先に立てていたものは止めない。
10. 伝える：`orca-flow qa-check $0 --show` の出力から、項目ごとの結果（`pass`・`fail`・`unverified`・`human`）と理由の一覧、崩れ（あれば）、`result.md` の絶対パスを人に示す。依頼のファイルに「QA の筋書き：」があれば、「QA の筋書きは組のプレビューで確かめるもので、このスキルでは流さない」と一言添える。最後に「前後の画面を見て違和感があれば、このタブで直す所を頼んでください」と伝える。直しを頼まれても、このスキルの中ではコードを直さず、頼まれた所を人に確かめてから、ふだんの会話として受ける。
